対象ファイル: Src/CXJ0560.frm（PXJ0560 受注納品書入力[共通EDI:アキタ]） 改修箇所: frm内 2箇所 作成日: 2026/08/05

本書の記述には 確認済（ソース・DB実データ・QRデコードで直接確認）と 推定（照合による推論）と 未確認（確認手段が未入手）を明示しています。

第3版からの訂正

第3版にあった「ハンク3（QRProcに1行追加）」を削除しました。不要であるうえ、有害になり得るためです。

  • ハンク3は B1lb_Ukeir.Caption = .受入 でQR解析値を採用する案でしたが、これは「QRの 1L の値が typQRAfter.受入 に格納される」という未確認の前提に依存していました。解析処理 QRConvert は共通モジュール ..\Module\QT10QSRB.bas（本フォルダ外・未入手）にあり、格納先を確認できていません。
  • さらに、もし 1L の値が .納入先工区 側に格納されていた場合、ハンク1が正しく取り出した受入を、ハンク3が空文字で上書きして壊します。
  • ハンク1・2（LostFocusの改修）だけでQR読取・手入力の両経路が成立することをソース上で確認しました（次章「なぜ2箇所で足りるか」）。ハンク1・2は格納先がどちらであっても動作します。

変更しない箇所と、その理由

重要

納入先 B1lb_Torcd.Caption = "1048" と 工区 B1lb_Kojyo.Caption = "" は固定値のまま残してください。

  • 確認済 ヘッダは 納入先(4桁)＋工区(2桁)＋受入(2桁)＋… の順で組み立てられます（CXJ0560.frm 5935-5949行）。
  • 確認済 ストアドは納入先を SUBSTRING(@HEAD,1,5)＝5桁で読み（受注JAMAチェック_アキタ 172行・178行）、受入を SUBSTRING(@HEAD,7,2) で読みます（同141行）。
  • 推定 現在は工区が空白のため5桁目が空白となり、SQL Serverの varchar 比較（末尾空白を無視）で '1048 ' = '1048' が成立していると考えられます。工区にQRの値（「␣1」）を入れると5桁目が変わり、納入先の判定（エラー1・2）が成立しなくなります。
  • 確認済 QRの納入先は9桁（400727246）で、自社の取引先CD 1048 と体系が異なります。また変換用ストアド EDI_取引先変換（4838行のコメント内で参照）は当DBのSPフォルダに存在しません。したがって納入先の固定値は必要です。

実装前に確認しておきたいこと

#未確認の事項確認方法本改修への影響
1QRConvert がQRの 1L（K2）をどのメンバに格納するかスキャン直後の画面で受入欄に「K2」が含まれることを目視確認（受入欄はQR解析値のまま残り、上書きされるのは隣のラベルのみ）受入欄のどこかに入っていれば動作する。まったく入っていない場合のみ要再検討
2アキタ様が各品番に割り当てている受入の全体像かんばん明細書（背番号＋受入・総枚数176／8ページ）と品番取引先マスタを全品番突合整備漏れの品番はエラー15でチケット全体が取込不可になる

テスト観点

  1. K2チケット（未取込のもの）をスキャン → 画面のラベルに K2 が表示され、受注テーブルに 受入K2 で登録され、出荷指示書に K2 が印字されること。
  2. 受入01のチケットをスキャン → 従来どおり受入01で登録され、動作が変わっていないこと。
  3. 手入力：受入欄に「K2」を入力してEnter → 受入K2 で登録されること（改修前は01になっていた）。左詰め2桁・4桁のどちらの入力でも同じ結果になること。
  4. 手入力：受入欄を未入力のままEnter → エラー4「受入未登録」となり、01で登録されないこと。
  5. 品番取引先マスタにその受入の行が無い品番を含むチケット → エラー15「品番未登録【N行目】」が表示され、チケットが1件も登録されないこと。
  6. 取引先受入マスタに無い受入（検証環境で一時的に行を外して確認） → エラー4「受入未登録」が表示されること。
  7. 同一チケットの再スキャン → 従来どおりエラー16「既に受注データが存在します」で二重登録されないこと。
  8. 後続帳票：納品書・検収・売上実績で、受入K2の受注が正しく扱われること（品番取引先マスタのK2行に契約先1048が設定済みであることはSQLで確認済み）。
運用上の注意

この改修は「全チケット一斉切替」です。リリース前に下記を済ませてください。

  • 確認済 品番取引先マスタの整備。現状（SQL実行結果）は 01:559品番／02:23／10:1／K1:1／K2:14／W3:4／W5:1 で、3W・K3・K5・P1・T2・W2・W6 は0品番です。これらの受入のチケットが来ると、その品番の行が無いためエラー15になります。
  • 推定 01の559品番は、受入が固定値01であった時代に登録された行です。アキタ様が実際に割り当てている受入と一致しているかは未確認のため、切替前にかんばん明細書と突合してください。
  • 確認済 切替日を決める。受注重複チェックのキーに受入が含まれる（SP 454-469行）ため、切替日をまたいで同じ伝票を再スキャンすると、01で取込済みの伝票をK2で二重登録できてしまいます。
  • 確認済 既に01で登録済みのデータは自動では直りません。受注テーブルの1048向けは受入01が720,299件（2011年〜・SQL実行結果）。遡ってK2にする場合はデータ補正と出荷指示書の再発行が別途必要です。
  • 確認済 手入力の運用周知。改修後は受入欄が未入力だとエラー4になります（従来は自動的に01が入っていました）。
